# __PROJECT__

Generated by `strictjava new` for Java 25.

## Validate

```bash
./gradlew --no-daemon formatCheck
./gradlew --no-daemon test
./scripts/strictjava.sh check --classpath "$(./gradlew -q strictjavaClasspath)" .
```

Set `STRICTJAVA_JAR=/path/to/strictjava.jar` or install `strictjava` on PATH
before running the strict profile check.

## Formatting

```bash
./gradlew format
./gradlew formatCheck
```

The build downloads the standalone google-java-format 1.36.1 release artifact
into the project-local Gradle cache and verifies its published SHA-256 before
execution.

## Tests

The starter test is dependency-free and runs on the Java 25 toolchain:

```bash
./gradlew test
```

Replace `src/test/java/app/MainTest.java` with domain tests as the project grows.

## Reproducible dependencies

The Gradle 9.8.0 wrapper verifies the distribution SHA-256 before use.

Dependency locking is strict:

```bash
./gradlew dependencies --write-locks
```

Dependency verification is also strict. When intentionally changing dependencies,
regenerate and review:

```bash
./gradlew --write-verification-metadata sha256 dependencies
```

JSpecify 1.0.0 is the only generated Gradle dependency.

## Docker

```bash
# Local source build
docker build -t __PROJECT__:dev .

# Reuse a distribution already built by Gradle
./gradlew installDist
docker build --target from-artifact -t __PROJECT__:ci .
```

Both paths use the same Java 25 runtime stage.

## Continuous integration

`.github/workflows/ci.yml` runs on pushes and pull requests and is reusable with
`workflow_call`. It validates the pinned wrapper, formatting, tests, strict
dependency state, strictjava, and the Docker runtime image.

The workflow pins strictjava to commit `__STRICTJAVA_REF__` so generated CI does
not silently change when strictjava's default branch moves.
